# 星穹铁道自动化 - 架构蓝图

> 本文档是后续 AI 编程的唯一指导蓝图。

## 一、项目目标

在日本环境下，全自动完成崩坏：星穹铁道的日常任务。电脑不休眠、保持登录不锁屏，脚本按计划执行，跑完即退出。

## 二、完整执行流程

```
Windows 任务计划程序（调度）
  │
  ▼
06:00：m7a_runner.py（启动入口）
  │
  ├─ 1. 以管理员权限进入正式链路
  ├─ 2. 启动 UU 加速器（如未运行）；失败时最多重启 UU 3 次，总共最多 4 轮
  ├─ 3. 将 UU 窗口置顶到前台
  ├─ 4. 统一处理已知 UU 弹窗（例如“你的UU已升级至最新版本”）
  ├─ 5. 若 UU 已在运行，先短轮询 `templates/uu_03.png`
  ├─ 6. 若 `uu_03.png` 已存在，则直接复用当前加速状态
  ├─ 7. 若 `uu_03.png` 不存在，再执行完整识图链路
  ├─ 8. 先等待 3 秒，再以 0.25 秒频率轮询 `templates/uu_01.png`
  ├─ 9. 识别成功后移动鼠标到中心
  ├─ 10. 等待 0.5 秒
  ├─ 11. 再次处理可能遮挡按钮的已知 UU 弹窗
  ├─ 12. 以 0.25 秒频率轮询 `templates/uu_02.png`，识别后点击
  ├─ 13. 等待加速生效并识别 `templates/uu_03.png` 作为确认
  ├─ 14. 退出 UU 启动链路前兜底最小化 UU 窗口，保留加速进程但不占用前台
  │
  ├─ 15. 启动 March7th Launcher.exe，传入任务参数和 `-e`
  ├─ 16. 轮询确认 `StarRail.exe` 或游戏窗口已真正出现
  ├─ 17. 看门狗监控（CPU 空闲 / 日志心跳；`main` 无硬超时）
  ├─ 18. 本轮新增日志出现“每日实训已完成/未完成”即确定业务结果
  ├─ 19. 汇报器继续读取同一轮日志，不再参与或改变业务结果
  ├─ 20. 看到“停止运行”立即解析；未停止则到 08:00 用已有进度解析
  ├─ 21. 规则层判定成功、失败、仍在进行或疑似卡住
  ├─ 22. DeepSeek V4 Flash 将结构化事实改写成人话；失败时使用规则摘要
  ├─ 23. 飞书发送交互式卡片，并将报告证据归档到 `logs/reports/`
  └─ 24. 记录日志，进程退出

08:00：cleanup_runner.py（收尾入口）
  │
  ├─ 1. 关闭 `StarRail.exe`
  ├─ 2. 清理残留的 March7th Launcher / Assistant 进程
  ├─ 3. 将 UU 窗口置顶到前台
  ├─ 4. 统一处理已知 UU 弹窗
  ├─ 5. 以 0.25 秒频率轮询 `templates/uu_03.png`
  ├─ 6. 点击 `uu_03.png` 对应按钮停止加速
  └─ 7. 记录日志，进程退出
```

## 三、任务时间表

| 时间  | 任务         | 参数       | 超时    |
|-------|-------------|-----------|---------|
| 06:00 | 完整运行     | main      | 无脚本硬超时；计划任务 2h10m 兜底 |
| 08:00 | 收尾关闭     | cleanup   | 600s    |
| 23:30 | 模拟宇宙     | universe  | 7200s   |

06:00 主任务和 08:00 收尾任务之间留足缓冲；即使主任务异常残留，08:00 也会主动关闭游戏并停止 UU 加速。
23:30 模拟宇宙任务保留在任务计划程序中，但默认禁用；该任务容易出问题，需要时再手动启用。

## 五、模块职责

### 1. `m7a_runner.py` — 核心执行器

- 命令行入口：`python m7a_runner.py <task> [--timeout SEC]`
- 启动 UU 前及加速完成后，验证 `hsr.hoyoverse.com:443`：域名必须解析为公网 IP 且 TCP 可达；检测到 TUN 常见的 `198.18.0.0/15` 假 DNS 时直接失败并通知“网络代理”，不再启动游戏后等待超时
- 调用 `uu_accel.py` 执行正式 UU 启动链路
- 启动 `March7th Launcher.exe` 并传入任务名和 `-e`
- 启动后先确认游戏进程和可见游戏窗口都出现，再进入常规看门狗，避免仅看到启动中的进程就过早开始心跳计时
- 游戏出现后优先发现并监控本次新建的 `March7th Assistant.exe`；只有找不到 Assistant 时才退回监控 Launcher，避免已有 Launcher 导致转发进程提前退出并误报成功
- M7A 启动前记录今天日志的字节位置，Assistant 结束后只检查本次新增内容，不能复用今天更早运行留下的成功标记
- `main` 任务只有在本次新增日志明确出现“每日实训已完成”时才判定业务成功；AI 无权修改此判定
- 业务结果确定后，汇报器等待 M7A “停止运行”；06:00 任务最迟 08:00 汇报，08:00 后的手动补发最多等待 2 小时
- 08:00 仍未停止时，根据日志更新时间、当前模块和重复错误判断“正常进行”或“疑似卡住”，并说明最后进度与依据
- 每日实训验收失败时，从本轮日志提取最后分数及“任务无法完成”项，例如：`实训400/500 卡体力/支援/差分`
- 看门狗监控：
  - `main` 不使用脚本硬超时；`universe` 保留显式硬超时
  - **CPU 空闲检测**：连续 15 分钟 CPU < 2% → 判定卡死 → 停止 `March7th Assistant.exe`
  - **日志心跳检测**：M7A 日志 10 分钟未更新 → 判定卡死 → 停止 `March7th Assistant.exe`
  - **启动宽限期**：60s 内不做卡死判定
  - 任一失败先保存全屏截图和本轮 M7A 日志到 `debug/`；绝不关闭游戏或 Launcher，保留现场供排查
- 统一退出码：
  - `0`：正常结束
  - `10`：UU 链路失败
  - `20`：M7A 启动器拉起失败
  - `21`：游戏未在启动确认时间内出现
  - `22`：M7A 非零退出
  - `23`：本次新增 M7A 日志未出现“每日实训已完成”
  - `24`：游戏网络预检失败（代理/TUN/DNS 或游戏端点不可达）
  - `30/31/32`：看门狗因硬超时（仅 `universe`）/ CPU 空闲 / 日志心跳停滞触发
- 日志输出到 `logs/YYYY-MM-DD.log`（用文件夹装起来，不散落到根目录）
- 主任务使用飞书交互式卡片汇报：
  - 标题保留 `✅️/❌️ 星铁完成/失败 MM-DD HH:MM 重试N`
  - 解析器按日志顺序记录有序事件流；卡片不显示时间戳，但严格保持奖励、副本、每日任务和最终完成节点的先后顺序
  - “每日实训”固定为第一主卡片，最终一项才显示“每日实训完成 500/500”
  - 单轮副本直接写总次数，例如“饰品提取·鎏金追忆 6次”；多轮才写“2轮×6次”
  - 只有剩余次数明确为 0，或实际完成次数覆盖计划总数时，才写“已完成”并更新长期养成状态
  - 每日实训、委托、无名勋礼三项奖励逐条放入“日常”
  - 其他事件放入“后续完成”；因开拓力不足保留的计划属于正常后续状态，不判异常
  - 文字尽可能少、条目尽可能多；不存在的掉落数量绝不编造
  - 已映射角色的副本统一追加“（角色 养成类型）”，包括执行成功和因条件不足保留的计划
  - 卡片末尾依次显示仍在进行的养成计划待办和按日期动态计算的提醒
  - AI 或通知失败不改变任务退出码

### 2. `uu_accel.py` — UU 正式启动链路

- 检测 UU 加速器进程是否已运行，未运行则启动
- 启动链路由单一 supervisor 管理：初始执行 1 轮，失败后最多重启 UU 3 次，总共最多 4 轮
- 单轮启动链路不负责重启，只负责跑业务步骤并抛出明确失败证据
- 每个图片步骤内部仍以 0.25 秒频率高频轮询，直到该步骤 timeout 到期
- 图片步骤 timeout 时保存 `debug/` 截图，并记录 step、reason、screenshot
- 可重试失败才会触发杀 UU + 等待 5 秒 + 重启；模板缺失、UU 程序路径缺失、非管理员等不可重试错误直接失败
- GUI 操作前要求当前进程已提权
- GUI 操作前校验主屏必须为 `2560x1440`；分辨率不匹配时截图并以不可重试错误退出，避免无效重启 UU
- 将 UU 窗口置顶到前台
- 若 UU 已在运行，先短轮询 `uu_03.png` 判断是否已经处于可复用的加速完成状态
- 若 `uu_03.png` 已存在，则直接复用，不再点击 `uu_01.png` / `uu_02.png`
- 若 `uu_03.png` 不存在，再继续完整启动链路
- 启动和收尾链路都通过统一弹窗处理层识别已知 UU 更新提示
- 对“你的UU已升级至最新版本”弹窗，先确认 notice 模板，再优先点击“确定”，失败时兜底点击关闭叉
- 如果弹窗已识别但无法点击“确定/关闭叉”，保存 `debug/` 截图并记录明确失败原因
- 先等待 3 秒，再以 0.25 秒频率轮询 `uu_01.png`
- 识别成功后将鼠标移动到中心
- 等待 0.5 秒
- 以 0.25 秒频率轮询 `uu_02.png` 并点击
- 等待加速生效后识别 `uu_03.png` 作为连接确认
- 启动链路通过统一窗口生命周期保护层退出；成功、失败、重启放弃时都兜底最小化 UU，尽量不让 UU 留在前台
- 收尾时复用同一套窗口置前和识图能力，点击 `uu_03.png` 停止加速
- 收尾链路复用同一窗口生命周期保护层；退出前也会兜底最小化 UU 窗口，不关闭 UU 进程
- 失败时截图存入 `debug/`

**当前阶段原则**：每完成一步，就直接并入 `ensure_uu_connected()` 正式链路；不保留平行测试脚本或一次性测试分支。

### 3. `cleanup_runner.py` — 收尾执行器

- 命令行入口：`python cleanup_runner.py [--delay SEC]`
- 先关闭 `StarRail.exe`
- 再关闭残留的 March7th Launcher / Assistant 进程
- 最后调用 `uu_accel.stop_uu_acceleration()` 点击 `uu_03.png` 停止加速
- 设计为幂等：游戏不存在、M7A 不存在、UU 不运行时都视为已完成
- 收尾成功不额外发送通知，避免重复打扰；收尾失败会发送飞书失败通知
- 手动测试例子：`uv run python run_elevated.py cleanup_runner.py --delay 10`

### 4. `feishu_notify.py` — 飞书通知模块

- 从 `.env` 读取 `FEISHU_WEBHOOK_URL` 和 `FEISHU_WEBHOOK_SECRET`
- 使用飞书自定义机器人签名发送 `interactive` 消息卡片
- 卡片结构由代码固定，AI 只负责组织各区块文字；程序不再复审或改写 AI 文案

### 5. `reporting/` — AI 汇报模块

- `log_parser.py` 只解析本轮 checkpoint 后的日志，以固定节点确定每日实训结果
- 卡住判据包括日志 10 分钟无更新，以及尾部连续至少 3 次已知失败（例如“未识别出任何界面”“截图失败：没有找到游戏窗口”）
- `ai_summarizer.py` 固定使用 `deepseek-v4-flash`、thinking enabled、`reasoning_effort=high`
- DeepSeek 直接组织最终卡片文本；程序不做内容事实复审或自动修复
- 程序只要求 DeepSeek 返回可解析的卡片 JSON；API 或 JSON 格式失败时使用规则摘要兜底
- `prompts/starrail_report.md` 独立维护不可变的输出协议和字段语义
- `prompts/starrail_report_few_shot.md` 提供成功、明确失败、后续超时和仍在进行的输入/输出示例
- `prompts/reporting_standard.md` 固定精简、排序、分类和角色标注规则，用户偏好无权覆盖
- `prompts/reporting_preferences.md` 只注入额外关注点和措辞倾向，并作为低优先级用户数据传给 AI
- `prompts/training_context.md` 保存自由培养背景；`training_plan.md` 保存结构化角色、副本映射和复选框状态
- `training_plan.py` 只在剩余计划为 0，或实际完成次数覆盖计划总数时自动勾选；AI 无权修改该文件
- 已完成养成项保留完成日期和证据，下一次只把未勾选项作为待办交给 AI
- `prompts/reminders.md` 保存日期型提醒；月卡剩余天数由程序按到期日期实时计算
- 历史回放同时按 checkpoint 与结束时间隔离同日多次运行；DeepSeek 未实际成功时禁止发送测试卡片
- DeepSeek 密钥缺失、超时或返回非法 JSON 时仍能发送规则摘要

### 6. `run_elevated.py` — 统一提权入口

- 手动测试 GUI 自动化时，统一通过该脚本拉起管理员进程
- 入口形式：`uv run python run_elevated.py <script.py> [args...]`
- 作用边界：只负责提权和转发命令，不承载业务逻辑

### 7. `templates/` — 图像模板

- 手动截取 UU 加速器界面中的关键元素
- 在当前环境（2K 分辨率 + 125% 缩放）下截取
- 当前正式链路使用 `uu_01.png`、`uu_02.png`、`uu_03.png`
- `uu_03.png` 在启动链路中用于确认加速完成，在收尾链路中用于点击停止加速
- `uu_update_notice.png`、`uu_update_confirm.png`、`uu_update_close.png` 用于处理 UU 更新提示弹窗，避免弹窗遮挡正式识图链路

## 六、技术选型

| 用途           | 库                        | 理由                           |
|---------------|--------------------------|-------------------------------|
| 图像识别       | pyautogui + pillow + opencv-python | 截图、匹配、点击链路直接可用 |
| 键鼠操作       | pyautogui                 | click/moveTo 简单够用           |
| 进程管理       | psutil                    | 进程树 kill、CPU 监控            |
| 日志           | logging（标准库）           | 零额外依赖，按天写文件             |
| AI 总结        | openai                    | 连接 DeepSeek OpenAI 兼容接口      |
| 本地密钥       | python-dotenv             | 从 `.env` 加载且不提交仓库          |

## 八、关键路径与配置项

## 九、Windows 任务计划配置要点

- `LogonType` 使用 `Interactive`，只在用户已登录时运行
- 使用最高权限运行
- 动作统一调用 `powershell.exe -File scripts/run_scheduled_task.ps1 ...`
- 脚本内部会 `Set-Location` 到项目目录，再按任务类型执行 `uv run python m7a_runner.py ...` 或 `uv run python cleanup_runner.py`
- `StarRail_Universe_2330` 保留但禁用，避免模拟宇宙异常影响稳定链路
- 取消交流电源限制
- 主任务计划任务时限为 2 小时 10 分钟，给 08:00 截止汇报预留发送余量；其他任务时限为脚本超时的 1.5 倍

## 十、注意事项

1. 电脑必须保持登录且桌面可交互，否则 GUI 自动化会失败
2. 显示器休眠不影响运行（截屏取的是 GPU 帧缓冲）
3. 星穹铁道客户端关闭"空闲时自动关闭"选项
4. 图像识别失败时自动截图到 `debug/`，方便事后排查
5. 125% 缩放下截取模板时，确保使用实际像素截图（非逻辑像素）
6. Apollo 会安装 SudoMaker 虚拟显示器并可能把主屏改成 1920x1080；当前已禁用 `ApolloService` 和该虚拟设备
7. 如 Apollo 再次改变显示环境，使用 `uv run python run_elevated.py scripts/disable_apollo_autostart.py` 恢复
8. 崩铁使用代理时应使用普通系统代理；TUN 模式若将游戏域名映射到 `198.18.0.0/15`，会触发游戏登录错误 `1001_1`，主任务会在游戏启动前终止并通知“网络代理”
