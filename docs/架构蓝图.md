# 星穹铁道自动化架构蓝图

本文档描述当前正式链路。实现以代码和测试为准，旧的根目录脚本入口不再使用。

## 一、运行目标

- 06:00 自动完成 UU 加速、启动 M7A 与每日任务，并在结果确定后发送飞书日报。
- 08:00 关闭游戏和 M7A，点击 UU 停止加速，但不强制退出 UU 进程。
- 23:30 模拟宇宙任务保留，因稳定性问题默认禁用。
- GUI、日志或网络异常时保留截图和本轮日志，游戏现场不因看门狗失败而被关闭。

## 二、正式流程

```text
Windows 任务计划程序
  -> scripts/run_scheduled_task.ps1
  -> uv run starrail-auto <command>
  -> workflows 业务编排
       -> 网络预检
       -> UU 启动/复用
       -> 网络复检
       -> M7A 启动与看门狗
       -> 当前运行日志验收
       -> DeepSeek 汇总
       -> 飞书卡片
```

06:00 主链路使用 `starrail-auto daily`。UU 已加速时识别 `uu_03.png` 并直接复用；否则执行 `uu_01.png` 移动和 `uu_02.png` 点击，再以 `uu_03.png` 验收。每个识图步骤以 0.25 秒轮询，步骤失败保存证据；Supervisor 最多重启 UU 3 次，总计最多执行 4 轮。任何出口都通过同一个窗口生命周期层尽力最小化 UU。

M7A 使用 `March7th Launcher.exe main -e`。启动前后均检查游戏域名必须解析到公网 IP 且 443 端口可达，以阻止 TUN Fake-IP 导致的登录假死。游戏进程和可见窗口同时出现后，看门狗优先监控本轮新建的 `March7th Assistant.exe`。

`main` 没有任意墙钟硬超时，只以本轮新增日志的“每日实训已完成”或“每日实训未完成”为业务边界。CPU 连续空闲 15 分钟或日志 10 分钟不更新才判定卡住。失败时只停止 Assistant，保留游戏和 Launcher 现场。

日报服务只读取当前运行的日志区间。M7A 出现“停止运行”后立即汇报；未结束时最晚 08:00 按现有进度汇报。成功判定由日志规则完成，AI 只负责人话组织，不反向修改程序结论或养成计划。

08:00 收尾使用 `starrail-auto cleanup`：关闭游戏和 M7A，识别并点击 `uu_03.png` 停止加速，最后最小化 UU。

## 三、目录边界

```text
starRail/
├── UserContext/                 用户直接编辑的 Markdown 上下文
├── docs/                        架构与外部工具事实文档
├── scripts/                     Windows 计划任务和一次性运维工具
├── src/starrail_auto/
│   ├── cli.py                   唯一命令入口
│   ├── settings.py              项目路径与 .env 加载
│   ├── workflows/               跨功能业务编排
│   ├── uu/                      UU 配置、进程、桌面层和 Supervisor
│   ├── m7a/                     环境、日志、看门狗与启动器
│   ├── reporting/               解析、养成状态、AI 和报告服务
│   │   └── prompting/system/     不允许用户覆盖的固定提示词
│   ├── integrations/            飞书等外部接口
│   └── windows/                 UAC 等 Windows 平台能力
├── templates/                   UU 识图模板
├── tests/                       与 src 对应的回归测试
├── runtime/                     日志、截图和报告归档，不入库
├── .env                         本地密钥，不入库
└── pyproject.toml               uv 依赖、打包与 CLI 配置
```

依赖方向固定为：`cli -> workflows -> feature service -> feature primitives`。`reporting` 不控制 M7A，AI 不控制事实判定，`UserContext` 不覆盖系统固定协议。

## 四、模块职责

### UU

- `config.py`：路径、模板和超时常量。
- `errors.py`：带步骤、证据和可重试属性的类型化异常。
- `processes.py`：启动、发现和终止 UU 进程。
- `desktop.py`：DPI awareness、窗口前置/最小化、识图、弹窗和截图。
- `service.py`：复用、完整启动、重启预算和停止加速的业务顺序。

GUI 操作必须在管理员且交互式桌面会话中执行。主屏必须为 2560x1440；不匹配属于不可重试环境错误，防止无意义地反复重启 UU。

### M7A

- `environment.py`：公网 DNS/TCP、游戏进程和可见窗口检查。
- `logs.py`：本轮字节边界、完成标记、失败阶段和证据。
- `watchdog.py`：Assistant 发现、CPU/日志心跳和证据保留策略。
- `runner.py`：启动 Launcher 并将生命周期转换为 `RunResult`。
- `workflows/daily.py`：串联网络、UU、M7A、报告和飞书通知。

关键退出码：`0` 成功、`10` UU 失败、`20` M7A 启动失败、`21` 游戏未出现、`22` M7A 非零退出、`23` 每日实训验收失败、`24` 网络预检失败、`30-32` 看门狗失败。

### 汇报

- `parser.py` 从日志提取按时间排序的事实、任务次数、奖励和异常。
- `training_plan.py` 读取并更新 `UserContext/养成计划.md`；只有明确剩余 0 或完成量覆盖计划时才自动完成。
- `prompting/system/*.md` 是固定核心协议、固定标准和 Few-shot，作为独立 system message 加载。
- `UserContext/*.md` 是低优先级用户数据，只进入运行时 user payload。
- `summarizer.py` 调用 DeepSeek Flash High；失败时使用确定性摘要。
- `service.py` 处理汇报边界、归档和飞书发送。

日报按日志顺序组织，不显示时间戳；每日实训为主块，日常奖励、后续完成、异常、养成待办和日期提醒分别成块。开拓力不足导致保留计划是正常后续状态，不是异常。

## 五、计划任务

| 任务名 | 时间 | CLI | 状态 |
|---|---:|---|---|
| `StarRail_Main_0600` | 06:00 | `daily --timeout 1800` | 启用 |
| `StarRail_Cleanup_0800` | 08:00 | `cleanup` | 启用 |
| `StarRail_Universe_2330` | 23:30 | `universe --timeout 7200` | 禁用 |

计划任务使用当前登录用户的 `Interactive` 登录类型和最高权限，保证桌面识图可用；设置 `IgnoreNew` 防止重复实例。注册脚本使用相同任务名先覆盖再注册，不会累积重复任务。

```powershell
# 管理员 PowerShell
uv sync
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/register_tasks.ps1
```

## 六、开发与排障

```powershell
uv sync
uv run pytest -q
uv run starrail-auto --help
uv run starrail-auto elevate uu start
uv run starrail-auto elevate daily
uv run starrail-auto elevate cleanup --delay 10
uv run python scripts/send_report_samples.py --set core
```

运行证据统一写入 `runtime/`：项目日志在 `runtime/logs/`，截图与故障日志在 `runtime/evidence/`，报告输入和输出在 `runtime/reports/`。不要将真实 `.env`、运行日志或截图提交到 Git。

## 七、设计依据

- Python 包采用 [PyPA 推荐的 src layout](https://packaging.python.org/en/latest/discussions/src-layout-vs-flat-layout/)，避免从仓库根目录误导入未安装源码。
- CLI 使用 [PyPA Entry Points](https://packaging.python.org/en/latest/specifications/entry-points/) 暴露 `starrail-auto`，并由 [`__main__`](https://docs.python.org/3/library/__main__.html) 支持模块执行。
- pytest 使用 [importlib 导入模式与独立 tests 目录](https://docs.pytest.org/en/stable/explanation/goodpractices.html)。
- 固定提示词通过 [`importlib.resources`](https://docs.python.org/3/library/importlib.resources.html) 从包资源加载，不依赖当前工作目录。
- GUI 计划任务使用 Windows Task Scheduler 的 [Interactive Token](https://learn.microsoft.com/en-us/windows/win32/taskschd/principal-logontype) 登录类型，以访问当前用户桌面。
