# 双游戏日报

## 目标

每天早上在飞书上一眼看清两款游戏各完成了哪些任务、哪里没成。卡片完全由程序按
固定规则生成，不调用 AI：同样的日志永远得到同样的卡片，不消耗 Token，也不会
出现模型编造的原因。（2026-10-01 起移除 DeepSeek 改写层；此前每天 1.2 万到 6 万
Token，且曾把星铁 09-29 的教程弹窗卡死误判成“内存不足”。）

## 卡片长什么样

```text
❌ 鸣潮 失败 · 10-01 05:52        标题：图标 + 游戏 + 结论 + 完成时间
用时 10分钟

**异常记录**                       只在没有全部完成时出现，排在最前
1. 讨伐：OK-WW 启动后 600 秒内没有开始讨伐
2. 日常：要等讨伐打到 5/5 才开始，本轮跳过

**今日任务**                       每个任务一行，行首符号表示结果
❌ 日常任务：没完成
❌ 讨伐强敌第3项：吸收声骸 0/5
```

行首符号：✅ 完成、❌ 没做成、⚠️ 做了但没确认/只完成一部分、⏸️ 按计划跳过、
ℹ️ 仅供参考。整体结论只有三种：全部完成（绿）、部分完成（橙）、失败（红）；
任何 ❌/⚠️ 行或异常说明都会让“全部完成”降为“部分完成”。

## 分层

```text
游戏日志切片 + 运行结果
  -> 应用 parser   只提取事实（星铁 RunReport / 鸣潮按任务的行）
  -> 应用 report   唯一的措辞层：事实 -> 任务行 + 中文异常
  -> 核心 GameReport  标题、颜色、栏目顺序、凭据脱敏，两款游戏共用
  -> 应用 service  发送（各自的飞书机器人）+ 原子归档
```

- 公共部分在 `packages/game-automation-core/.../reporting/`：`report.py`
  （GameReport、状态符号、`settle_status`）、`feishu.py`（卡片与签名发送、
  `card_text` 文字预览）、`redact.py`（凭据脱敏）、`archive.py`（原子 JSON 归档）。
- 星铁：`apps/starrail/src/starrail_auto/reporting/`，失败阶段（看门狗、UU、网络等）
  在 `report.py` 的 `STAGE_TEXT` 翻译成中文。
- 鸣潮：`apps/wuwa/src/wuwa_auto/reporting/`，英文失败原因在 `reasons.py` 翻译，
  未收录的原样截短展示；同日讨伐/日常分开结算时由 `day_rollup.py` 合并。

## 验收与回放

两款游戏的 `report` 命令都用历史归档重建卡片，打印文字版并写 `.preview.json`，
从不发送：

```powershell
uv run starrail-auto report 2026-09-29_0
uv run wuwa-auto report 20261001_054202_farm_echo_confirmed_retry_daily
```

## 边界

- 只写本轮真正执行过的任务；邮件不进入鸣潮报告；未确认的活跃度不能写成已领取。
- 卡片、归档和预览统一做凭据脱敏；`.env` 中的值不进入任何输出。
- 每次运行只在链路末尾发送一张最终卡片；预览模式不触发 Webhook。
- 上游 OK-WW/M7A 源码不在此管线内修改；上游更新后只需重新解析当前运行日志。
