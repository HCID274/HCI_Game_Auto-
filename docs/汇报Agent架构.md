# 双游戏汇报 Agent

## 目标

星铁和鸣潮都使用同一套“事实优先、语言可重写”的汇报管线。游戏适配器只负责从本轮日志和运行结果生成事实；共享 Agent 层负责证据切片、脱敏、DeepSeek 调用、Token 统计和诊断边界；各游戏只保留自己的术语、章节顺序和完成判定。

## 数据流

1. 读取当前运行的日志片段，不把历史日志混入本轮。
2. 解析器生成不可由模型覆盖的事实项，并生成带 `L<number>` 的证据包。证据包限制大小，优先保留运行首部、末尾状态和异常行。
3. 将结构化事实、用户 Markdown 偏好和证据分层传给 DeepSeek。模型只能改写措辞、整理章节和提出带证据引用的诊断。
4. 本地校验 JSON、事实 ID、任务/次数/状态、列表一一对应关系和诊断引用。任何校验失败都保留已计费 Token，回退确定性报告。
5. 归档事实、叙述、诊断和 `ai_token_usage`；发送前只组装一张最终卡片。预览模式不触发 Webhook。

## Token 统计

归档字段 `ai_token_usage` 包含 `input_tokens`、`output_tokens`、`total_tokens`、`output_input_ratio`、缓存输入、推理 Token、模型和 `available`。比例定义为 `output_tokens / input_tokens`，缺少供应商用量时不估算。

## 安全和边界

- Agent 不得新增任务、掉落、计数、奖励或完成状态；未确认的活跃度不能改写为已领取。
- 诊断必须引用当前证据行，且不能与确定性状态相反。
- 日志、结构化事实、回退文本、卡片诊断和归档统一做凭据脱敏。
- 上游 OK-WW/M7A 源码不在此管线内修改；上游更新后只需重新解析当前运行日志。
