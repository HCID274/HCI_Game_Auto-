# UU 与网络排障

## UU 状态机

1. 未运行则启动进程；已运行则先前置窗口。
2. 处理已知更新弹窗。
3. 短轮询 `uu_03.png`；存在表示加速已开启，直接复用。
4. 不存在时等待 3 秒，轮询 `uu_01.png` 并移动鼠标。
5. 等待 0.5 秒，轮询并点击 `uu_02.png`。
6. 等待加速生效，再以 `uu_03.png` 验收。
7. 任意出口统一最小化 UU。

图片步骤以 0.25 秒轮询到各自 timeout。可重试步骤失败保存截图后由 Supervisor 终止 UU、等待 5 秒并重启；最多 3 次重启。程序缺失、模板缺失、权限或分辨率错误不可重试。

## 更新弹窗

先识别 `uu_update_notice.png`，再点击 `uu_update_confirm.png`，找不到时尝试 `uu_update_close.png`。Notice 已出现但动作模板均不存在时必须保存截图并抛错，不能盲点坐标。

## 网络与代理

- M7A 前后都检查 `hsr.hoyoverse.com:443`。
- DNS 必须至少返回一个公网 IP；`198.18.0.0/15` 属于常见 TUN Fake-IP，不能视为游戏网络可用。
- TCP 预检失败时报告“网络代理”，不要启动游戏后等待界面超时。
- 校园网自愈脚本检测到 UU 进程时应提高故障阈值并避免重启 WLAN；但真实持续断网仍应恢复。不要把单次 DNS 抖动当成网卡故障。
- 远程单向连接环境修改网络守卫前，先证明变更不会主动断开 Wi-Fi；优先阈值和观察窗口改动，不先重启网卡。

## 证据

记录 attempt、step、reason、retryable、screenshot 和已使用重启次数。识图失败先看截图中的分辨率、弹窗和 UU 当前状态，再判断是否需要新模板。
