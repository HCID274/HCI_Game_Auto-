# AI 汇报与飞书

## 数据流

```text
本轮 M7A 日志
  -> parser.py 提取有序事实
  -> training_plan.py 更新确定性养成状态
  -> composer.py 组合三段固定 system prompt + 一段运行时 user JSON
  -> DeepSeek Flash High 组织人话
  -> 飞书交互式卡片
```

程序负责日志边界、成功状态、任务次数和养成完成条件。AI 负责分类后的措辞与合理失败归纳，不需要程序再次检查 AI 的文字，也不输出 `source` 字段。

## 提示词边界

- `核心协议.md`：字段语义和事实边界。
- `固定标准.md`：精简、排序、分类和固定表达。
- `标准示例.md`：成功、失败、超时和进行中的 Few-shot。
- `UserContext/汇报偏好.md`：可选额外关注点，不能覆盖固定标准。
- `UserContext/培养背景.md`：自由角色背景。
- `UserContext/养成计划.md`：结构化 Markdown 状态，由程序更新。
- `UserContext/日期提醒.md`：按到期日期动态计算。

涉及提示词的新需求先判断是固定系统规则还是用户偏好。固定输出顺序、字数、分类和事实边界放系统目录；角色、当日关注点和措辞偏好放 `UserContext`。

## 卡片规则

- 标题以 `✅️/❌️ 星铁完成/失败` 开头，时间后置到分钟并显示重试次数。
- 按日志顺序输出，不显示时间戳；每日实训最终结果放该块最后。
- 每日实训、委托和无名勋礼奖励分别列入“日常”。
- 开拓力不足保留计划列入“后续完成”，不列异常。
- 单轮副本直接写总次数；有角色映射时追加“（角色 类型）”。
- 养成待办与日期提醒放卡片末尾。
- 只有真实异常才显示异常块。

历史回放默认只验证，不发送：

```powershell
uv run python scripts/send_report_samples.py --set core
```

只有显式传入 `--send` 才向真实飞书 Webhook 发送。
