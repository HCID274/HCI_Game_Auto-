# OK-WW 日志覆盖审计

## 审计边界

- 安装版本：OK-WW `v3.5.18`。
- 源码位置：本机安装目录中的 `src/task`，不修改上游源码。
- 可用历史日志：`2026-07-26` 至 `2026-07-28`；本机没有更早的 OK-WW 日志，
  因而不能虚构 30 天样本。
- 接入原则：源码支持且历史日志真实出现，并存在稳定的成功或异常边界，才进入
  日报解析器。

## 主流程覆盖矩阵

| OK-WW 功能 | 源码支持 | 历史出现 | 当前处理 |
| --- | --- | --- | --- |
| 无音区 | 是 | 是 | 统计成功领取场次；排除未领宝箱重试；每场按源码固定 60 结晶波片 |
| 凝素领域 | 是 | 否 | 暂不接入，等待真实日志样本 |
| 模拟领域 | 是 | 否 | 暂不接入，等待真实日志样本 |
| 每日活跃度奖励 | 是 | 是 | 至少 100 点时确认领取；否则只报告执行领取操作，最终点数不确认 |
| 先约电台 | 是 | 是 | 仅进入有效领取分支时报告“已执行奖励领取操作” |
| 梦魇巢穴日常声骸 | 是 | 是 | 统计实际吸收；不可达目标进入异常记录 |
| 幻梦游园 | 是 | 是 | 仅本轮运行并出现完成标记时报告；“此前已达 6000”不算本轮完成 |
| 声骸合成 | 是 | 否 | 暂不接入，等待真实日志样本 |
| 讨伐强敌 | 是 | 是 | 保留 GUI 一基编号；只统计可见重开界面或成功吸收声骸，不把脱战结果误作击杀；Boss 名称仅由用户 Markdown 补充 |
| 讨伐死亡恢复 | 是 | 是 | `char dead` 与 `Revive Failed` 同时出现才介入；退本回血后在同一小时截止时间内补剩余吸收数 |
| 讨伐声骸吸收 | 是 | 是 | 在 DailyTask 前运行；只统计 `FarmEchoTask` 的成功吸收标记，达到 5/5 才完成，不足时在 1 小时内补齐 |

## 已验证的关键边界

1. `current stamina: -36` 是 OK-WW 内部的剩余消耗预算，不是游戏最终体力，
   不能与初始体力相减。无音区消耗改由成功领奖场次计算。
2. `claim daily reward via  coordinate` 只证明脚本点击了固定坐标，不单独证明
   奖励存在或活跃度已满。
3. `farm echo walk find true` 属于梦魇巢穴，而
   `farm echo walk_find_echo True` 属于讨伐强敌；必须带任务类前缀解析。
4. `Garden current: [6000...]` 和 `weekly garden already completed` 是既有状态，
   不能算本轮完成周常。
5. `Daily Task Completed` 是整个日常编排结束边界；子任务页面或点击完成不能替代
   业务事实标记。
6. `2026-07-28` 真实运行证明 `start wait in combat` 和
   `FarmEchoTask:farm echo walk_find_echo None` 都可能在同一场尚未结束的战斗中
   重复出现，不能作为击杀证据；击杀后的重开按钮只统计击杀，不能增加声骸吸收
   进度。新版精确任务只使用结构化吸收数判定完成。
7. 讨伐副本中的 `FarmEchoTask.revive_action` 会直接返回失败；宿主恢复不能改动
   上游源码，而是在清理前复用 OK 普通副本已存在的“关闭死亡弹窗、退出副本、
   传送回血”流程，并使用本地虚拟 HID 保持 Windows 的真实鼠标设备前置条件。
8. 补跑中每个待吸收目标最多允许 12 次战斗检测循环，以容忍没有掉落和同一场
   战斗的脱战误判；精确完成目标只按成功吸收停止。全量 5 次对应最多 60 个检测
   循环，吸收阶段最多 1 小时，并继续受总控 3 小时最终保险约束。
9. 游戏重开后若仍停在已击败场地，等待场景稳定 4 秒，再通过“退出 / 重新挑战”
   确认框复用场地。该旧重开动作只负责进入下一场，不计入本轮结构化完成数。
10. VIIPER 本地设备处理等待为 20 秒，覆盖 usbip-win2 偶发超过默认 5 秒的附加
    延迟；虚拟 HID 的启动与销毁仍由工作流上下文托管。

## 后续扩展方式

当凝素领域、模拟领域或声骸合成首次真实运行后，保存该次
`runtime/runs/<run_id>/ok-current-run.log`，同时补充成功、跳过和失败样本测试，
再更新本表。不得只根据源码中的任务名直接生成完成事实。
